## 1. Error al desplegar en Vercel (variables de Supabase)

**Causa más probable:** en `.env.local` de Edgar, las dos variables de Supabase tienen un **espacio delante del valor**:

```
NEXT_PUBLIC_SUPABASE_URL= https://...        ← espacio después del "="
NEXT_PUBLIC_SUPABASE_ANON_KEY= sb_publishable_...
```

En local funciona porque Next recorta los espacios al leer `.env.local`. Al copiar/pegar o importar el archivo en Vercel, el espacio puede quedarse dentro del valor → URL inválida o clave rechazada.

**Qué hacer:**
1. En Vercel → Project → Settings → Environment Variables, crear (o reescribir sin espacios):
   - `NEXT_PUBLIC_SUPABASE_URL` = `https://urrnkwrwatcifypdwfwc.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = la clave **publishable** (`sb_publishable_...`). Nunca la secreta.
   - `NEXT_PUBLIC_SITE_URL` = el dominio de Vercel (en `.env.local` está `http://localhost:3000`; no copiarlo tal cual).
   - `ROODADA_MODO_PRUEBA` = `1` mientras sea solo para testers (no indexa en buscadores).
   - `ANALYSIS_DATABASE_URL` **no** hace falta en Vercel (solo scripts locales).
2. Marcarlas para Production **y** Preview.
3. **Redesplegar** (Deployments → Redeploy). Las `NEXT_PUBLIC_` se meten en el build: si se añaden después, no se aplican hasta un nuevo build.
4. `.env.local` no está en git (`.gitignore` ignora `.env*`), así que Vercel no lo ve nunca: las variables hay que ponerlas a mano.

Si sigue fallando: pasad el texto exacto del error del log de build. Si dice «Faltan NEXT_PUBLIC_SUPABASE_URL o NEXT_PUBLIC_SUPABASE_ANON_KEY» (`src/lib/supabase/server.ts`), las variables no llegan al build (pasos 1-3).
